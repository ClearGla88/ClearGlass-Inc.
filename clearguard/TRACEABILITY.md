# Traceability: specification → control → test → state

Source: [SPEC.md](SPEC.md), the owner's Guardian Sentinel text of 2026-11-16. Capability states use the specification's own terms (section 1). **VERIFIED** here means unit-tested in this repository against the requirement in the row. Nothing is **VALIDATED** (shown fit for real use), and nothing can be **ACTIVE**, because this build has no live host integration. The machine-readable record is `clearguard_core/data/capabilities.json`, and `tests/unit/test_capability.py` fails if it claims a state it has no evidence for.

| § | Requirement | Control | Tests | State | Open / residual risk |
|---|---|---|---|---|---|
| 1 | Six capability states; no promotion without evidence; ACTIVE only with healthy live inputs | `capability.py` (`promote`, `registry_problems`) | `test_capability.py` | VERIFIED | Evidence references are checked for existence, not for quality. |
| 2 | Per-detector operating envelope; capability-specific limitations | `health.py` (`assess`, per-detector `limitations`); contract `operating_envelope` | `test_health.py` | VERIFIED (logic only) | Every envelope for a sensor detector is empty: no review has defined one.
