# ClearShield audit, 2026-11-19

Scope: `clearshield/` as committed at `a117bc9` (`1.0.0.dev0`), and the fixes made in response (`1.0.0.dev1`). Reviewer: an AI coding assistant working at the owner's request. **This is not an independent third-party security review**, which remains a production blocker.

## What could be verified

- The source package exists in this repository: 13 modules plus an entry script (3,146 lines at `a117bc9`, 3,416 after the fixes), with tests, docs and a CI workflow. It is a clean-room implementation written on 2026-11-13. It is **not** the owner's original ClearShield v1 code, which has never been supplied.
- The owner's reported v1 results (nine tests passing, a Linux smoke test passing, no deployments) still cannot be verified, because the original code and its evidence are not available. Nothing below confirms or reuses them.
- Tests were run here: 206 collected on Python 3.11.18, 3.12.3 and 3.13.18, plus the Linux smoke script, as root and as uid 65534. The commands and counts are in RELEASE_CHECKLIST.md.
- Nothing was deployed, installed as a service, or run against a real host's configuration. No firewall rule was changed and no microphone was opened.

Status labels: **V** verified from source and tests run here · **U** user-reported, not verified · **P** proposed, not implemented · **?** unknown or untested.

## 3. Threat model summary

SECURITY.md holds the full model. The key points:

- **Assets:** watched files, the baseline, the HMAC key, the audit history, host availability, and people's privacy.
- **Trust boundaries:** auth log text and WAV files are attacker-controlled. `/proc` is trusted only until root is compromised. The state directory is trusted only at 0700/0600 and owned by the monitoring user.
- **Same privileges as the monitor, or root:** nothing local is trustworthy after that point. The HMAC key is readable, so the attacker can rewrite history, state and baseline. Root can also hide sockets and files. Only evidence that was off the host before the compromise survives: an exported checkpoint, or the remote storage of roadmap stage 1.
- **HMAC is not a signature:** anyone who can verify a tag can forge one. An Ed25519 signature would let a third party verify without being able to forge, but it does not help against an attacker on this host.
- **Non-goals:** prevention, firewall changes, malware scanning, packet capture, monitoring people, identifying a sound's source, measuring dB SPL, and collecting raw audio.

## 5. Release-readiness decision

**Evaluation-ready, not production-ready.**

- **Met:** the source exists and is tested on three interpreters as root and as an unprivileged user. Every advertised capability maps to code and tests. Defects found in this audit are fixed with regression tests. Claims are bounded: detection only, dBFS not dB SPL, tamper-evident not tamper-proof, and no agency certification claimed.
- **Blocking production:** real-host validation of SSH parsing, the journal, IPv6 beyond loopback, big-endian hosts and microphone hardware; F6; a private reporting channel; legal review of PRIVACY.md; off-host evidence storage; an independent review.
